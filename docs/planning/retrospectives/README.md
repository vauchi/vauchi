# Retrospective Documents

This directory contains retrospective documents written after successful implementation.

## Purpose

After all tests pass (unit + E2E), write a retrospective to capture:
- What went well
- What could be improved
- Problems detected during implementation
- Lessons learned

If problems are detected, they are distilled into new problem descriptions that feed back into the problem-to-solution flow.

## Naming Convention

`YYYY-MM-DD-<feature-name>.md`

## Template

```markdown
# Retrospective: [Feature Name]

## Summary
[Brief description of what was implemented]

## What Went Well
- [Point 1]
- [Point 2]

## What Could Be Improved
- [Point 1]
- [Point 2]

## Problems Detected
[If any problems were found during implementation]

### New Problem Descriptions
[Problems to be fed back into the flow]

1. **[Problem Title]**
   - Description: [...]
   - Impact: [...]

## Lessons Learned
- [Lesson 1]
- [Lesson 2]

## Related Documents
- Implementation plan: [link]
- Knowledge docs: [links]
```
