# Vauchi Dependency Map

## Core Dependency Graph

```text
vauchi-core (standalone, no workspace deps)
    ↑ git dep (branch = "main")
    ├── cli/
    ├── tui/
    └── linux-gtk/

vauchi-core (path dep)
    ↑
    ├── vauchi-platform  (sibling in core/ workspace, forces network-rustls)
    └── e2e/           (path deps to both core and relay)

relay/ — INDEPENDENT (no vauchi-core dependency)
```

## Rust Repos: Git Dependencies

All downstream repos use:

```toml
vauchi-core = { git = "https://gitlab.com/vauchi/core.git", branch = "main" }
```

| Repo | Depends On | Features |
|------|-----------|----------|
| `cli/` | vauchi-core | (default) |
| `tui/` | vauchi-core | (default) |
| `linux-gtk/` | vauchi-core | (default) |
| `e2e/` | vauchi-core (path), vauchi-relay (path) | — |
| `relay/` | **Nothing** (independent) | — |

## Local Path Overrides (Cargo.toml)

For local development, `just setup-path-overrides` injects a
fenced `[patch.<gitlab>]` block at the **bottom of each consumer's
`Cargo.toml`** (not `.cargo/config.toml` — modern cargo silently
ignores `[patch]` there; see problem record
`2026-05-03-cargo-path-override-broken`):

```toml
# >>> setup-path-overrides BEGIN — DO NOT COMMIT
# Auto-generated by: just setup-path-overrides
# Strip with: just clean-path-overrides   (or git pre-commit hook)
[patch.'https://gitlab.com/vauchi/core.git']
vauchi-core = { path = "../core/vauchi-core" }
vauchi-app = { path = "../core/vauchi-app" }
# <<< setup-path-overrides END
```

The recipe also runs `cargo update --offline -p vauchi-...` so
Cargo.lock points at the local paths. Both the fence in Cargo.toml
AND the path-sourced entries in Cargo.lock are local-dev artifacts —
the pre-commit hook in `scripts/hooks/pre-commit` blocks committing
either. `just check-path-overrides` (also run on `session-init`)
verifies cargo actually resolved vauchi-* via local paths and not
to whatever rev `Cargo.lock` pinned.

### Override Coverage

| Repo | vauchi-* deps patched |
|------|-----------------------|
| `cli/` | vauchi-core, vauchi-app |
| `tui/` | vauchi-core, vauchi-app |

## Core Workspace Internal

```toml
# core/Cargo.toml
[workspace]
members = ["vauchi-core", "vauchi-platform"]

# core/vauchi-platform/Cargo.toml
vauchi-core = { path = "../vauchi-core", version = "0.1.0", default-features = false, features = ["network-rustls"] }
```

vauchi-platform forces `network-rustls` (no OpenSSL for iOS/Android cross-compilation).

## Mobile Bindings Consumption

### iOS (SPM)

```swift
// ios/ depends on vauchi-platform-swift via Swift Package Manager
// Package.resolved pins:
//   version: "0.1.5"
//   revision: "249089a01..."
//   repository: "https://gitlab.com/vauchi/vauchi-platform-swift.git"
```

vauchi-platform-swift's Package.swift downloads pre-built XCFramework:

```swift
.binaryTarget(
    name: "VauchiPlatformFFI",
    url: "https://gitlab.com/api/v4/projects/vauchi%2Fcore/packages/generic/vauchi-platform/{version}/VauchiPlatformFFI.xcframework.zip",
    checksum: checksum
)
```

### Android (Gradle/Maven)

```kotlin
// android/app/build.gradle.kts
dependencies {
    implementation("app.vauchi:vauchi-platform:0.1.2")
}
```

Published to GitLab Maven registry. JNA runtime required:

```kotlin
implementation("net.java.dev.jna:jna:5.14.0@aar")
```

## Shared Locales

**Location**: `locales/` (own repo: `vauchi/locales`, cloned by `just setup`)

Files: `en.json`, `de.json`, `fr.json`, `es.json` (754 keys each)

Key format: `section.element` (e.g., `contacts.empty`, `action.save`)

Runtime loading: `i18n::init(resource_dir)` loads from JSON files at startup. `load_locale_from_bytes()` for CDN hot-reload.

Consumed by:

- **Native desktop frontends**: Loaded via `i18n::init()` (linux-gtk)
  or platform-native mechanisms (macos, windows)
- **iOS/Android**: Via `init_locales(resource_dir)` UniFFI export +
  `get_available_locales()`
- **Core tests**: Uses `core/vauchi-core/locales/` copy

Validate: `just sync-locales`

## Version Pinning Strategy

| Repo Type | Strategy | Details |
|-----------|----------|---------|
| Rust downstream | `branch = "main"` | Always latest, no tag pinning |
| vauchi-platform (internal) | `path = "../vauchi-core"` | Workspace sibling |
| iOS app | SPM version pin | `"0.1.5"` + commit SHA + checksum |
| Android app | Maven version pin | `"0.1.2"` |
| Distribution repos | Auto-updated by CI | Version injected via pipeline trigger |

**No semantic versioning tags on git deps** — Rust repos always track `main`.

## Common Pitfalls

1. **Forgetting `just setup-path-overrides`** — CI uses the git dep,
   local builds without the patch fetch from GitLab and read whatever
   rev `Cargo.lock` pinned. Run `just check-path-overrides` to verify.
2. **vauchi-platform forces rustls** — if you add a dependency that
   pulls in OpenSSL, Android/iOS builds break.
3. **Committing the path-overrides fence** — Cargo.toml is tracked.
   The pre-commit hook blocks it; if it slips by, CI fails because the
   path is meaningless on the runner. Run `just clean-path-overrides`
   before staging.
4. **Relay is independent** — don't try to add vauchi-core as a
   dependency to relay (relay only consumes `vauchi-protocol`).
